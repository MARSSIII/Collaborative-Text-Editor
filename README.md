# Совместный текстовый редактор

Сетевое многопользовательское приложение для совместного редактирования текстовых документов в реальном времени. Несколько пользователей могут одновременно работать с одним документом, подключаясь к общему серверу. Каждый пользователь видит изменения и курсоры остальных участников мгновенно.

### Функциональные требования

1. Сервер должен уметь принимать одновременные TCP-подключения от клиентов на указанном порту и корректно обрабатывать отключение клиента, освобождая его ресурсы и уведомляя остальных участников документа.
2. Пользователь должен иметь возможность зарегистрироваться и авторизоваться по логину и паролю.
3. Пользователь должен иметь возможность создать новый документ, просмотреть список существующих документов, подключиться к документу и отключиться от него. Владелец документа может его удалить.
4. Каждый открытый документ обрабатывается в отдельном потоке. Входящие операции от клиентов поступают в lock-free очередь документа, обрабатываются последовательно внутри потока документа и рассылаются остальным подписчикам.
5. Автосохранение документов на диск выполняется в отдельном потоке с настраиваемой периодичностью, не блокируя процесс редактирования. После перезапуска сервера документы восстанавливаются из сохранённых данных.
6. Сбор позиций курсоров всех пользователей и их периодическая рассылка выполняются в отдельном потоке.
7. Асинхронное логирование событий сервера выполняется в отдельном потоке через lock-free очередь, не блокируя обработку операций.

### Логика редактирования

1. При подключении к документу пользователь получает полное актуальное содержимое документа и текущий номер ревизии.
2. Пользователь может вставлять и удалять текст в произвольной позиции документа. Локальные изменения применяются мгновенно, без ожидания подтверждения от сервера.
3. При одновременном редактировании несколькими пользователями возникают конфликты позиций. Сервер разрешает их с помощью алгоритма Operational Transformation (OT). Каждая входящая операция трансформируется относительно всех операций, применённых после ревизии, на которой базировался клиент.
4. После применения всех операций содержимое документа гарантированно одинаково у всех подключённых пользователей (свойство конвергенции).
5. Пользователь может отменить свою последнюю операцию (Undo) и повторить отменённую операцию (Redo). Undo отменяет только собственные операции пользователя, не затрагивая чужие.
6. Пользователь может выполнить поиск и замену текста в документе. На клиенте эта операция выполняется в фоновом потоке, чтобы не блокировать интерфейс при больших документах.

### Клиентская часть

1. У пользователя должно быть окно подключения для ввода адреса сервера, порта, логина и пароля.
2. После авторизации отображается список доступных документов с возможностью создать новый или подключиться к существующему.
3. В редакторе отображается текст документа с нумерацией строк. Курсоры других пользователей отображаются уникальным цветом с подписью имени рядом с курсором. Выделение текста другими пользователями отображается полупрозрачным цветом соответствующего пользователя.
4. Сбоку отображается панель со списком пользователей, подключённых к текущему документу, с цветовыми метками.
5. В строке состояния отображаются текущая строка, столбец, номер ревизии документа и количество подключённых пользователей.
6. Сетевой обмен с сервером, трансформация входящих операций (OT Worker) и локальное автосохранение документа выполняются в отдельных потоках, не блокируя интерфейс.
7. Пользователь может экспортировать текущий документ в локальный текстовый файл.
